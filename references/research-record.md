# 长调研台账与恢复

在用户选定的项目输出目录保存 `research-log.md`；名称已存在且属于其他任务时另选描述性名称，不覆盖。台账只含为恢复所需的脱敏摘要，不自动同步外部服务。依赖技能建议的 `/tmp` 等位置只用于临时材料；持久交付位置以用户和当前项目约定为准。

按任务复杂度记录，不要求凑行数：

- 目标、用户限定的平台/时间/数据范围、当前结论及仍会改变决策的问题。
- 本轮实际使用的工具或 Skill 路径、访问日期；平台状态用“未尝试 / 已检索 / 访问受限”，不能将未尝试当作没有结果。
- 脱敏查询词；若脱敏仍会暴露秘密，只保存通用问题和省略原因。
- 每条证据的原始公开 URL、作者/项目、发布日期（可得时）、读到的范围、主张与反例。私有签名 URL 不保存，可用用户本地材料编号引用。
- 验证状态“已实测 / 资料声称 / 尚未验证”，实测需注明环境或版本、实际操作、观察结果和范围；单次测试不能代表批量稳定。
- 路线取舍、失败类别、已完成工作、下一步和交付物路径；相反证据不得删除。

恢复时先读台账，再核对用户目标是否变化、文件是否存在、关键资料是否过期。已确认过且未变化的操作不重复做；重新验证会影响决策的动态事实。用户改变范围时更新台账，保留旧结论的日期和失效原因，不伪装旧结论一直正确。

用户要求清理时，列出本任务临时文件和持久报告，按明确范围处理。不要清理其他任务数据；不要将个人资料放入 Skill 的测试夹具或分发包。
